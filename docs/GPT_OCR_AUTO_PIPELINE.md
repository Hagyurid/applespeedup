# 에쁠가속기: ChatGPT OCR · 자료 검증 · 선목차 · 자동 저장 (2026-10-09)

**기준 저장소**: `Hagyurid/applespeedup`, `develop/aplus-v2`. 기존 `study` 변경 금지, Render 자료 이전 제외.

## 제품 요구사항

- GPT가 **시각 원본에 접근할 수 있는 경우에만** 스캔 PDF·사진·손글씨·수식·표를 최대한 판독한다.
- GPT가 과목별로 선택된 다른 자료·교재·공신력 있는 참고 자료와 대조해 전사본/인식본의 오류 후보를 판정한다.
- 원본은 변경하지 않는다. 원문 인식본, 교정본, 근거 `source_id`, 불확실한 부분을 별도로 보존한다.
- **OCR/전사본 검토 완료 이전**에는 해당 자료를 GPT 제작용 검증된 검색 자료로 사용하지 않는다.
- **모든 GPT 자료 제작 전** 반드시 목차/문서 구조를 내부 DB에 먼저 기록한다. 이어서 절/문항 묶음을 작성하며 각 단계에서 결과물을 자동 저장한다.
- 작업이 끊기면 저장된 목차와 섹션, 노트 버전을 조회해 그 다음부터 계속한다.
- 사용자가 입력한 과목·유형·제목·주차·기출 연도는 OCR로 덮어쓰지 않는다. 구 DB의 학년도별 `offering_id`는 최종적으로 제거할 구조적 기술 부채다.

## 이미 개발 브랜치에 추가된 서버 구성 (Sites 실사용 미연결)

- `sites/ai-pipeline.mjs`
  - `saveSourcePageImage/getSourcePageImage`: PNG/JPEG 페이지 프리뷰를 권한 검사 후 R2에 저장하고 GPT MCP 응답의 `image` 블록으로 전달.
  - `saveReviewedPage/getReviewedPage/finalizeSourceReview`: 페이지별 OCR/전사본 원문·교정본·근거·미확인 항목 저장. 모든 페이지가 있어야 검색용 청크 게시.
  - `beginGeneration/saveGenerationOutline/saveGeneratedSection/getGenerationProgress`: 명시 선택된 검토완료 원본 사용, 목차 선저장 강제, 절 단위 저장과 정리본 버전 자동 갱신.
- `sites/mcp-core.mjs`: 관련 GPT 도구 선언. 실행 엔진이 아닌 **도구 호출 인터페이스**이며, 실제 ChatGPT의 Tool 사용·이미지 블록 지원은 Sites 배포 후 검증 필요.
- `sites/http.mjs`: 같은 저장 경로를 서버 API로 호출. `/api/ai/source-page-image` 업로드는 PNG/JPEG 1MiB 제한 및 source 권한 확인.
- `db/schema.ts`, `drizzle/0002_*.sql`, `drizzle/0003_*.sql`: D1 데이터 모델과 마이그레이션.
- `web/connected.js`: 이미지 파일은 브라우저에서 **축소 JPEG 프리뷰**만 생성해 R2에 보내며, **문자 인식은 하지 않는다**.

## 실사용에서 빠진 부분 — 완료로 표시 금지

1. **실제 사이트 `/mcp`는 현재 HTTP 503으로 닫혀 있음**. 호스트용 인증/OAuth/플러그인 권한과 함께 안전하게 개방하기 전 ChatGPT OCR이나 자동 저장을 실제 수행하지 못한다.
2. **PDF 페이지 이미지를 만드는 브라우저 래스터라이저**가 아직 없음. PDF.js 등으로 `PDF → 각 페이지의 JPEG/PNG`를 수행해야 이미지 MCP를 통해 GPT가 실제 페이지를 읽을 수 있다. 이는 OCR이 아니라 이미지 변환이다.
3. 최초 원본의 실제 PDF 페이지 수를 검증하는 메타데이터/프로세스도 미완료. 현재 검토 완료 도구는 호출자가 제공하는 총 페이지 수를 기준으로 확인한다. 실제 문서 페이지 수와 대조하기 전에는 완전성 확인으로 취급하면 안 된다.
4. **전사본 업로드 즉시 GPT가 실행되지는 않는다.** 별도의 모델 API 호출 비용을 쓰지 않는 조건에서는 사용자 ChatGPT 대화에서 플러그인 작업을 시작한 뒤 해당 작업 내 순차 호출·저장이 자동으로 진행된다.
5. OCR의 정확도가 100%라는 주장 금지. 모델이 원본/근거를 재검토한 결과와 사람이 확인한 결과를 구분하도록 향후 review_status를 세분화해야 한다.
6. **개요 선저장 및 자동 저장은 현 시점에는 `notes` (Markdown 정리본) 출력**에 연결돼 있다. SolvePad 문제팩·CASIO 결과물 전용 스키마 저장은 추후 타입별 Writer를 구현해야 한다.
7. 개별 섹션 저장과 노트 갱신은 동시 요청에 안전하게 직렬화/재시도되어야 하며, 운영 D1과 실제 MCP 이미지 렌더에서 재검증해야 한다.
8. **서버 구조는 현재 과도기 `offering_id` 의존**. 최종 정책은 자료마다 과목+유형 필수, 일반 자료 주차 선택/기출 연도 선택이다. 이를 DB/API/MCP 공통 `course_id` 스키마로 마이그레이션해야 한다.

## 후속 우선순위

P0. 실제 ChatGPT Sites 호스트에서 인증된 MCP 연결 및 GPT의 `image` 응답 인식 검증; `/mcp` 무인증 공개 금지.
P1. PDF.js 브라우저 페이지 변환 및 페이지 수 검증·일시정지·재개·프리뷰 업로드. iPad/노트북의 메모리 테스트.
P2. 전사본/이미지 PDF 페이지 검토 상태 표시, 출처 대조와 미확인 부분 UI.
P3. `course_id` 직접 참조 마이그레이션 및 GPT 제작실의 주차/개별 체크 선택을 서버 source_ids와 연결.
P4. 생성 자동 저장을 Note 외 SolvePad 문제팩·시험 압축·CASIO 결과물로 확장.
P5. 과목별 GPT OCR → 검토 → 목차 → 생성 → 저장을 실제 사이트에서 통합 테스트하고 소유자 승인 후 게시.

## 안전 보장

- 파일 원본은 R2, 메타데이터와 페이지 교정 결과는 D1에 저장한다.
- GPT가 교정했더라도 재현 가능하도록 **원본 인식 텍스트와 근거**를 함께 보존한다. 현재 페이지 재저장 시 최신 인식본으로 대체되므로 최초 OCR 버전 이력까지 보존하려면 추가 감사 테이블이 필요하다.
- 다중 계정 사용자는 서버에서 과목 권한 및 각 source_id 소속 여부를 검증한다.
- GPT가 원본 이미지를 실제로 받지 못했다면 OCR 완료라고 주장해서는 안 된다.
