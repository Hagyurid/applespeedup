## 변경 내용

- `.openai/hosting.json`에 기존 스키마와 호환되는 논리 바인딩 `DB`와 `BUCKET` 지정. Cloudflare 운영 리소스는 Sites가 배포할 때 연결합니다.
- `db/schema.ts`와 생성된 `drizzle/` SQL을 운영 스키마의 기준으로 사용합니다. `sites/schema.sql`은 Node/SQLite 테스트용 자동 생성 사본입니다. 요청 처리 중 테이블을 생성하지 않습니다.
- `sites/auth.mjs`에서 Sites의 `oai-authenticated-user-id` 및 `oai-authenticated-user-email`을 사용합니다. 본문·임의 `x-user-id`·모델 API 키·서비스 우회 토큰을 사용자 신원으로 사용하지 않습니다.
- `sites/runtime.mjs`를 Worker 진입점에 연결했습니다. 사용자별 인가를 기존 리포지토리에서 다시 검사하고, 파일은 권한 검사 후 다운로드합니다.
- 최초 운영 배포는 **자료 변경 잠금 상태**입니다. `APLUS_WRITES_ENABLED`는 기본값과 Sites 설정 모두 `false`이며, 실제 로그인·접근 경계 확인 전에는 자료 변경을 허용하지 않습니다. 호출자가 헤더나 JSON으로 잠금을 해제할 수 없습니다.
- 같은 과목/강의 및 동일 내용 업로드는 기존 레코드를 재사용합니다. 텍스트 청크 생성 중 과학 표기와 위첨자를 변형하지 않습니다.
- 강의를 바꾸면 해당 강의의 작성 중 자료와 정리본을 복원합니다. 강의 전환 중 로딩이 실패해도 이전 강의의 자료 목록을 새 강의 아래 표시하지 않습니다. 초안은 현재 탭 메모리에만 보관되며 영구 저장본은 D1을 기준으로 합니다.
- 한 페이지에 모든 폼을 쌓던 구성을 강의·자료·GPT 작업·정리본 네 화면으로 나눴습니다. 노트북은 고정 사이드 메뉴, 860px 이하 iPad·휴대폰은 고정 하단 메뉴를 사용하며 가로 스크롤을 차단합니다. 현재 화면은 URL 해시와 브라우저 뒤로가기에 연동됩니다.
- 정리본 신규 저장에는 요청 ID를 사용하고, 수정에는 기대 버전을 사용합니다. 요청 재전송이나 동시 편집으로 정리본이 중복 생성되거나 이전 내용이 덮어써지지 않도록 처리했습니다.
- 브라우저 도구 2개는 화면의 선택 강의 조회와 검색을 사용합니다. 별도 Site MCP와는 다릅니다. 실제 WebMCP 컨텍스트 검증은 미실시입니다.
- 녹음 업로드·자동 전사·OpenAI 모델 API·Render 연결은 추가하지 않았습니다. 기존 `Hagyurid/study`는 수정하지 않았습니다.

| 빌드된 Worker 통합 검사 | 10개 통과 | workerd/Miniflare의 로컬 D1·R2. 로그인 헤더는 테스트에서 주입 |
| 내부 D1 스키마 적용 | 28개 SQL 문 적용 성공 | 로컬 에뮬레이션만 적용, 운영 DB 미확인 |
| 실제 ChatGPT 로그인 | 사용자 확인 | 자동화 결과가 아니며 메뉴·반응형·쓰기 동작은 별도 검증 필요 |
| 브라우저 클릭·모바일·iPad | 미실시 | v0.7.0-preview.2 실제 사이트에서 사용자 검토 필요 |

재현 명령:

```sh
pnpm install --frozen-lockfile
pnpm run check
pnpm test
pnpm run typecheck
pnpm run build
pnpm run test:worker
```

Worker 검사는 영구 저장 없이 새 로컬 D1/R2로 실행하고 마지막에 폐기합니다. CI에도 동일한 검사 흐름을 추가했습니다. GitHub Actions의 원격 실행 결과는 해당 실행이 끝난 후 별도 확인해야 합니다.

3. 두 번째 실제 계정이 필요하면 명시적으로 초대한 뒤 타 사용자 자료 접근 거부를 확인합니다.
4. 이후 PDF 페이지 추출, 과목 정보 편집·삭제, 버전 복원, 작업 상태/재개 UI를 완성합니다.
