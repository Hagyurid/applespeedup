# 기술 구조와 UX 결정

## 핵심 구분
- `course`: 과목 자체. 공통 성격, 정리 선호, 용어.
- `offering`: 학년도·학기·교수·분반 단위의 실제 강의. **현재 강의 자료 선택의 기준**.
- `source_asset`: 특정 개설 강의에 속하는 강의 슬라이드, 전사본, 교재, 강의계획서, 과거 기출.
- `course_fact`: 시험 유형, 출제 특성, 선배 후기 등. `official/observed/reported/inferred`를 꼭 구분.
- `unit_map`: 주차·단원과 자료 페이지를 연결.
- `note / note_versions`: 사용자가 편집하는 정리본 원본과 변경 이력.
- `job / checkpoint`: ChatGPT AI 작업 중간 저장·재개용 기록. 백그라운드 AI 프로세스가 아님.

## AI 없이 가능한 작업
파일 업로드, 현재 학년도 검색·필터, 편집·저장, 필기·시험 결과 열람, 요청문 생성, 기본 문서 출력.

## ChatGPT 안에서만 수행할 작업
강의 구조 해석, 내용·문제·해설 생성, 기출 비교, 전사본 용어 교정 등. 플러그인 MCP 도구가 **실제로 설치되어야** 데이터 조회·쓰기 가능.

## UX
- 대시보드: 가장 최근 과목 + 할 일 및 진행 상태.
- 과목: 과목 프로필 → 현재 개설 강의/과거 개설 강의. 교수의 특성은 연도별 기록.
- 자료함: 자료 유형·연도 필터. 전사본은 TXT/MD 또는 붙여넣기; 음성 녹음 입력 미지원.
- 제작실: 과목/학년도(맥락 유지) → 템플릿 9개 → 범위 → GPT 요청 복사.
- 정리본: 웹 원본 저장, 단원별 편집, 비교·버전 복원은 실서비스 단계.
- 작업 기록: pending/partial/complete, 실패 시 이어하기.
- 모바일: 상단 스크롤 탭, 한 번에 한 작업, 바닥 고정 주요 액션은 추후 인터랙션 검토.

## 규모에 맞는 아키텍처
약 3명 사용 기준 모듈형 단일 앱. 마이크로서비스 분리나 별도 AI API 결제 없음. D1/R2 저장소·Site 서버측 유효 인증과 소유권 확인은 필수다. 인증되지 않은 `x-user-id` 헤더를 사용자 ID로 신뢰하지 않는다.

## 보안·성능
- 파일 내용은 불신 입력: 프롬프트 인젝션을 시스템 지시로 처리하지 않는다.
- 과거 학년도 자료는 연도별 분리, 출처를 확인할 수 없는 내용은 추정으로 표기.
- 중복 요청은 job_id로 확인, 노트는 revision 충돌을 감지해 덮어쓰기 방지.
- 검색은 offeringId 필터를 우선; 전체 DB 검색 금지.
- D1에는 구조화 DB·검색 메타데이터만, 실제 원본은 R2에 저장.
- 파일 업로드는 최대 크기·MIME·바이러스 점검 정책 필요, 업로드 원본 직접 공개 금지.
- Sites 공개 베타 런타임과 계정 한도는 Work 프로젝트에서 검증.
