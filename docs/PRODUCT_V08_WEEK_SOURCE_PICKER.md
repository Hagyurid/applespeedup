# 에쁠가속기 v0.8 정보 구조·자료 선택 설계 (2026-10-09)

> 상태: **설계 확정 제안, 미구현**. 대상 저장소 `Hagyurid/applespeedup` / `develop/aplus-v2`. `study`는 읽기 전용 참고. 본 문서는 현재 게시된 Sites에 자동 적용되지 않는다.

## 1. 분류 원칙

자료의 **필수 분류는 과목(course_id) + 자료 유형(source_type)** 2개다. 일반 자료는 주차를 선택 등록하고, **기출·시험자료(past_exam)만 주차 대신 기출 연도(exam_year)를 입력**한다. 유형 전환에 따라 해당 입력창만 보여준다.

- **주차는 일반 자료의 선택 속성**이다. **기출은 선택적 연도(exam_year)**만 저장하고 주차와 동시에 입력하지 않는다. 과목 자체의 학년도·학기·교수·분반·단원·시험 범위 분류는 신설하지 않는다.
- 한 자료는 0개, 1개 또는 **여러 주차**를 가질 수 있다. 예: `[3,4]`; 지정하지 않으면 `미지정`.
- 주차는 선택 가능한 숫자 1~30으로 저장한다. UI에서 주차 선택은 선택적이며, 기간이 다른 파일은 `미지정`도 허용한다. 추후 사용 수요를 보고 범위를 설정에서 조정 가능하게 한다.
- 원본 종류: `lecture_slides`(강의자료), `transcript`(전사본), `reference`(교재/참고자료), `past_exam`(기출/시험자료), `other`(기타). 기출 연도는 자료 한 건에 하나의 4자리 연도로 기록하며, 모르면 비워 둔다.
- 제목·원래 파일명·등록일·PDF 페이지·파일 해시·추출 상태는 운영 정보일 뿐 **별도의 필수 분류**가 아니다.
- GPT 결과물도 `course_id`에 직접 저장하고 유형(정리본/요약/문제팩/계산기)으로 구별한다. 필요 시 생성에 사용한 주차를 표시하되 별도의 결과물 폴더 분류로 강제하지 않는다.

## 2. 자료 등록

`강의자료 > 자료 등록`에서 사용자는 **과목(상단 공통 선택), 유형, 직접 정하는 제목, 원본 파일 또는 텍스트, 주차(일반 자료) 혹은 연도(기출)**만 입력한다.

- 주차 선택: `미지정`, `1주차` ... `30주차` 중 다중 선택. 3~4주차에 걸친 PDF는 3, 4 모두 선택.
- 일반 자료의 주차와 기출의 연도는 기본값 `미지정`으로 보존. **업로드한 원본 파일명·PDF 내부 제목·OCR 텍스트를 보고 자동으로 주차·연도·자료명을 결정하지 않는다.**
- `past_exam` 선택 시 주차 입력을 숨기고 `기출 연도(선택)` 숫자 입력을 표시한다. 일반 자료에서는 연도 입력을 숨긴다. 자료명을 직접 입력하지 않았다면 저장을 막는다(원본명 자동 대체 금지).
- 파일 한 건만 저장한다. 여러 주차에 해당하더라도 파일을 복제하지 않는다. 파일의 `original_file_name`은 원본 다운로드·감사 목적으로만 별도 저장하며 목록·GPT 응답 제목에 쓰지 않는다.
- 수동 변경: 주차 추가·제거, 유형 변경, 제목 수정, 삭제(확인). 내용 변경 시 해시/추출 재처리.
- 업로드 후 `ready`(검색 가능) / `pending`(추출 대기) / `failed` 등 상태를 명확히 보여준다.
- 주차 미지정 자료도 검색과 GPT 선택에서 배제하지 않는다.

## 3. 자료함 화면

상단: 공통 과목 선택.

탭/필터: `전체 | 강의자료 | 전사본 | 교재·참고 | 기출·시험 | 기타` + 검색어. **일반 자료 탭은 `주차 전체/1~30주차/미지정`; 기출 탭은 `연도 전체/연도별/미지정`**으로 동적 전환한다.

표/카드: `체크박스(자료 제작실에서 사용할 때) · 사용자가 입력한 제목 · 유형 · 주차 또는 기출연도 배지 · OCR/추출 상태 · 미리보기·수정`.

주차별 보기에서 여러 주차를 가진 파일은 어느 해당 주차를 필터링해도 동일 source_id 한 건으로 표시된다.

## 4. GPT 제작실의 자료 선택 패널 — 중요

데스크톱/가로 iPad에서 2열 레이아웃:
- 왼쪽(약 58~65%): 제작 모드, 지시사항/요청 범위, 결과 형식, 작업 시작, 상태.
- 오른쪽(약 35~42%): **선택한 과목의 실제 자료 목록**, 검색, 유형 탭, 주차 그룹, 자료 체크박스, 선택된 파일 수·목록.
- 오른쪽 패널은 화면 내부에서 독립 스크롤하되 **페이지 가로 스크롤은 금지**한다. 목록이 길면 그룹 접기/펼치기.
- 좁은 iPad/휴대폰: `1. 자료 선택 → 2. 제작 설정 → 3. 선택 확인/시작` 세 단계로 분리해 좁은 화면에서 두 열을 억지로 압축하지 않는다. 과목 선택은 모든 단계에서 상단 고정.

주차별·개별 선택이 모두 가능한 **하나의 선택 목록**:
1. `1주차 [선택]` 체크 시 그 주차에 연결된 자료의 source_id를 일괄 선택.
2. `2주차 [선택]`도 누르면 중복 없는 합집합으로 선택(여러 주차에 중복 등장하는 파일은 1건).
3. 각 파일 체크로 개별 선택/제외할 수 있다. 주차 전체 선택 후 특정 파일만 제외 가능.
4. 주차 필터/유형 필터/검색어를 바꿔도 **이미 선택한 파일은 해제되지 않는다**. 선택 요약에서 언제든 확인·해제 가능.
5. `미지정 자료` 그룹도 별도 표시하고 선택 가능.
6. `선택 자료: N개`가 전체 목록 위/아래에 항상 보인다. `선택 모두 해제` 제공.
7. `추출 대기` 또는 `추출 실패` 자료는 목록에 보이지만 **GPT 본문 분석용 선택은 비활성**; 원본만 참조하는 예외가 있다면 해당 기능을 별도로 명시한다.
8. 과목을 바꾸면 이전 과목의 source_id가 새 과목에 적용되지 않도록 **선택 상태를 초기화**한다. 저장 전 변경 중인 지시문은 보존할 수 있다.
9. 같은 파일을 주차 선택과 개별 선택 양쪽에서 체크해도 한 번만 GPT에 전달한다.
10. 범위 지시(`1~3주차 요약`)는 **자유 텍스트**이다. 실제 근거 파일은 체크한 source_id 목록으로 확정된다. 임의로 같은 과목의 나머지 파일을 끌어오지 않는다.

**처음 실행 시 자동으로 과목 전체 자료를 선택하지 않는다.** 자료가 0개 선택이면 `자료 기반 생성` 버튼은 비활성이고 안내 문구를 표시한다. 사용자가 명시적으로 자료 없는 일반 요청을 선택한 경우만 별도로 허용할 수 있다.

예시:
- `1주차` 전체 선택: 강의슬라이드 + 전사본 2건
- `2주차` 전체 선택 추가: 슬라이드 + 전사본 2건 추가
- `1주차 전사본`만 해제: 최종 3건으로 생성
- `기출`은 묻지 않고 자동 추가하지 않는다.

## 5. 저장 계약 및 서버 경계

권장 DB 목표:
- `courses`: 과목
- `source_assets(id, course_id, source_type, title, exam_year, original_file_name, ...)`: 자료의 주 소유 과목과 유형
- `source_weeks(source_id, week_number)`: 해당 자료의 선택 주차. `PRIMARY KEY(source_id,week_number)` / `CHECK(week_number BETWEEN 1 AND 30)`
- `source_pages`/`source_chunks`: 기존 파일별 원문 추출
- `notes(course_id, note_type, ...)`, `problem_packs(course_id, ...)`, `calculator_projects(course_id, ...)`
- `jobs(course_id, ..., selected_source_ids_json, selected_source_snapshot_json)`: 생성 시점에 **확정된 source_ids**, 필요한 해시·제목·유형·주차 스냅샷
- `private_attempts(user_id,pack_id,...)`: 개인 풀이·오답 기록 (서버 측 권한 보호)
- DB에서 `offerings` 및 `offering_id` 의존을 제거. 현재 자동 생성되는 학년도별 강의 레코드도 사용하지 않는다.

API 예시:
- `GET /api/sources?course_id=...&type=...&week=...` (선택 과목의 허용된 자료만)
- `POST /api/sources` with `{course_id,type,title,weeks:[1,2],...}`
- `PATCH /api/sources/:id` with `{title?,type?,weeks?}`
- `POST /api/jobs` with `{course_id,mode,scope,selected_source_ids:[...]}`
- `GET /api/notes?course_id=...`, `GET /api/problem-packs?course_id=...`
- MCP: `list_course_sources(course_id,type?,week?)`, `search_course_sources(course_id,query,type?,week?)`, `get_source_content(source_id)`, `save_note(course_id,...)`, `save_problem_pack(course_id,...)`.

모든 source_id를 서버에서 인증 사용자의 해당 과목과 매칭해 검증한다. **사용자가 선택하지 않은 원본은 모델에 전송하지 않는다.** 과목 전환·자료 삭제·추출 실패·선택 시점과 실행 시점 간 변경을 검사하고, 문제가 생기면 조용히 바꾸지 않고 재확인을 요청한다.

특히 `past_exam`을 포함했다면 모델의 활용 방식을 지침에 포함: 현재 강의 자료의 사실 근거와 구분, 기본적으로 출제 형태 참고. 데이터 분류에 연도를 요구하지 않는다.

## 6. 기존 study에서 복구해야 할 도구

- **Study Note**: Markdown → WYSIWYG/MathJax 수식 렌더, 형광펜/이미지/슬라이드, Word/PDF, 버전 복원
- **SolvePad**: `solvepad.problemPack.v5` 호환 문제팩, 아이패드 펜 입력, 채점/힌트, 북마크/오답, 개인 풀이 기록
- **CASIO**: blueprint, PRGM 검증, TXT/ZIP 내보내기, 사용법/결과 보기
- **콘텐츠 파이프라인**: PDF/DOCX/PPTX 내용 추출, 작업/체크포인트, GPT MCP 저장
- 사이트는 외부 OpenAI API·Render 없음, 음성 업로드 없음.

## 7. 개발 순서 및 합격 조건

1. 현재 Sites 스키마/운영 데이터를 확인한 후 안전한 DB 개편 계획 작성(이전 Render 데이터와 별개). 소스/노트/작업을 `course_id`로 직접 참조.
2. `source_weeks` 추가, 자료 업로드 및 수정 시 주차 다중 입력, `미지정` 허용. 자료 종류는 필수.
3. **전역 과목 선택** 구현, 모든 화면과 같은 선택 상태 공유.
4. GPT 제작실 우측 자료 목록 + 주차 일괄 선택·개별 선택·부분 제외·중복 제거·선택 요약 구현.
5. 선택 source_id를 서버 작업과 MCP 검색/생성까지 전달; 서버에서 사용자가 선택한 파일만 접근하는지 검증.
6. Study Note 문서형 렌더와 SolvePad를 우선 이식, 다음 CASIO. 정리본·문제팩 저장을 같은 과목과 연결.
7. 페이지 텍스트 추출, 저장 권한/버전/멀티디바이스/사용량 검사, 실제 Sites E2E 후 게시.

**합격 테스트**:
- `과목 + 자료 유형` 두 필수 분류만 있음. 주차는 선택, 0/1/여러 값 허용.
- 1주차·2주차 자료를 선택하고 해당 주차 공통 파일 1건이 중복 집계되지 않음.
- 주차 그룹 선택 뒤 전사본 1건만 체크 해제할 수 있음.
- 유형/검색 필터 전환 시 이미 선택한 파일 유지.
- 과목 전환하면 다른 과목 자료 선택 초기화.
- `미지정` 자료가 목록/검색/선택에 노출.
- 추출 대기 PDF를 '검색 가능'으로 속이지 않음.
- 모바일은 자료 선택·제작·확인을 단계로 진행, 가로 드래그 필요 없음.
- 실제 GPT 작업에는 **최종 선택한 자료 ID만** 전달됨.
- 서버 쓰기 잠금·MCP 미완료 상태에서 실제 AI 자동 저장 완료로 오인하게 하지 않음.


## 8. 원본명과 입력 메타데이터 분리 계약 (2026-10-09 추가)

- 클라이언트에서 File.name은 `original_file_name`에만 저장한다. 사용자가 입력한 `title`, `source_type`, `weeks` 또는 `exam_year`가 자료 목록/검색/요청문과 DB의 유일한 기준이다.
- 원본이 `IMG_3821_scan_final.pdf`여도 입력값 `{title:"촉매반응공학 기말고사",type:"past_exam",exam_year:2024}`로 저장한다. 원본명·OCR 결과는 제목/연도를 변경할 수 없다.
- 자료 유형 변경 시 일반 자료는 `weeks`만, 기출은 `exam_year`만 저장한다. 과거 유형 입력값은 클라이언트 임시 값으로 되돌릴 수 있어도 서로 다른 유형의 필드가 DB에 남지 않도록 서버에서 검증한다.
- OCR로 인식된 페이지, 텍스트, 오류 가능 수식은 `source_id`로 연결된 **본문 데이터**다. 분류 메타데이터와 별도 저장하고 사용자가 원문을 고칠 때 제목·유형·주차/연도가 변경되지 않는다.
- OCR 구현 사양, 콘텐츠 안전성, 영구 저장 설계는 `docs/OCR_PIPELINE_V08.md` 참고.

## 구현 단계 명시 (2026-10-09)

- **현재 개발 브랜치의 선행 구현:** 자료 등록 UI는 자료 유형에 따라 선택 주차/기출 연도를 전환하며, 저장한 제목은 사용자 입력을 사용한다. 백엔드는 기존 `source_assets.weeks_json`(신규 마이그레이션 `0001_source_weeks`)과 `year_reference`(기출 연도)를 임시 저장 칼럼으로 사용한다. 동일 바이너리 재등록 시 사용자가 입력한 분류·제목으로 기존 자료 메타데이터를 갱신한다.
- **구현되지 않은 최종 구조:** 과목 직접 연결(`course_id`, `offering_id` 제거), 정규화된 `source_weeks` 테이블, GPT 우측 선택 패널, OCR, 실제 Sites 배포 및 데이터 쓰기 잠금 해제는 아직 별도 개발이 필요하다.
- 위 **최종 DB 목표**와 선행 구현의 저장 방식은 다르며, 최종 전환 시 드리즐 마이그레이션·기존 신규사이트 데이터 안전성 검증을 먼저 한다. 기존 Render 데이터 이전은 범위 밖이다.
